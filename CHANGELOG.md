# Changelog

All notable changes to context-link. Dates are release-tag dates. Versions before 1.0.0 were reconstructed from git history.

## [Unreleased]

Upgrading: migration 014 re-indexes C and C++ files only (their hashes are blanked; other languages keep theirs, nothing is deleted).
Migration 015 likewise blanks the hashes of Go files, so the first index after upgrading re-indexes them and extracts their routes.

### Added
- **Index runs are serialised across processes.** `IndexRepo` takes an OS advisory lock on `<db-path>.lock` (`LockFileEx` on Windows, `flock` on Unix) after its in-process run slot and holds it until the run ends, so `index`, `extract` (which indexes first) and `serve` (`reindex_project`, `--watch`) in separate processes no longer interleave their multi-transaction runs on one database. A run that finds the lock held logs `waiting for another index run on <db>` once and polls every 150 ms until it gets the lock or its context ends (Ctrl-C, `reindex_project` timeout). Readers never take the lock. The lock file (mode 0600, empty) stays next to the database; the OS releases the lock when a process exits, so a crash cannot leave a stale lock. New package `internal/store/filelock`; `store.DB.Path()` returns the path `store.Open` was given (DBs with no path are not locked). `golang.org/x/sys` is now a direct dependency (it was already indirect).
- **Go HTTP routes** for Gin, Echo, chi and net/http (`find_http_routes`, `extract` entry points). Registrations: Gin/Echo `r.GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS(...)` (Echo also `CONNECT`/`TRACE`), `Any` (method `ALL`), Gin `Handle(method, path, ...)` / `Match([]string{...}, path, ...)`, Echo `Add` / `Match`; chi `Get/Post/...`, `Handle`/`HandleFunc` (`ALL`, or the method of a `"GET /x"` pattern), `Method`/`MethodFunc`; net/http `http.Handle`/`http.HandleFunc`, `mux.Handle`/`mux.HandleFunc` and `http.DefaultServeMux`, with Go 1.22 `"METHOD /path"` and host patterns. Methods may be `http.MethodGet`-style constants. Prefixes from the same file: Gin/Echo `.Group("/p")`, chained (`v1 := api.Group("/v1")`) and inline (`r.Group("/a").GET(...)`); chi `r.Route("/p", func(r chi.Router) {...})` nesting (from the call's AST ancestry), `r.Group(fn)` and `r.With(mw)`. The framework comes from the file's imports (`github.com/gin-gonic/gin`, `github.com/labstack/echo[/vN]`, `github.com/go-chi/chi[/vN]`, `net/http`). A call counts only on a router receiver — a constructor result, a group of one, or a parameter/struct field of a router type — and only with a handler argument (name, selector, func literal, wrapper call), so `http.Get(url)`, `client.Get(...)`, Gin/Echo context `Get`/`GET`, a cache's `Get("k", fn)` and `http.NewRequest(...)` are not routes. Handlers: a name or selector (`handlers.List`, `h.Show`, `http.HandlerFunc(f)` unwrapped) is linked; func literals and other wrappers are inline.
- Route handlers in another file are linked: when the handler isn't a function of the route's own file, it is resolved like a call at the registration (`internal/indexer/resolve.go`: same language; the file, its directory/package, then imported files; a qualifier bound by an import such as `handlers.List` only inside the imported package; no repo-wide bare-name guess for Go). This applies to every language with routes (a JS handler imported from `./users` now links too) and is what Spring and Django routes will use. The handler's name and receiver are stored (migration 015: `routes.handler_name`, `routes.handler_qualifier`), and every index run relinks routes left without a handler, so re-indexing only the handler file no longer drops the link.
- `store.NormalizePath` maps chi/Spring regex parameters (`{id:[0-9]+}`, `{n:\d+}`, `{c:[A-Z]{3}}`) to `:param`, Go 1.22 `{path...}` to `*`, and drops Go's `{$}` end anchor (Gin `*filepath` was already `*`).

### Changed
- Express member handlers (`router.delete('/x', ctrl.remove)`) resolve through their object like a method call (`ctrl` from a default or namespace import → the imported file; any other object → the route's file only) instead of by bare name in the route's file.

### Fixed
- **C++ methods defined outside their class** get the class prefix from the qualified name's scope: `int Foo::bar() {}` is `Foo.bar` (was `bar`), the same name as a member defined in the class body. Naming rules (documented on `cppScopedName`): only the last scope segment is kept, so `ns::Foo::bar` is `Foo.bar` and `A::B::m` is `B.m`; template arguments are dropped (`Foo<T>::bar` → `Foo.bar`); constructors, destructors and operators keep their C++ names (`Foo.Foo`, `Foo.~Foo`, `Foo.operator==`). A scoped namespace function `ns::helper` becomes `ns.helper` with kind `method`: the grammar can't tell a namespace from a class, so it is treated as a qualifier, not checked against the repo's classes. Unqualified functions inside `namespace ns { ... }` keep their bare name, as before.
- More C++ definitions are symbols: out-of-class destructors, operators, nested or namespace-qualified scopes and pointer/reference returns (`Foo::~Foo`, `Foo::operator==`, `ns::Foo::bar`, `int* Foo::p()`, `Foo& Foo::self()`), which no pattern matched before, and member functions defined in the class body (`int get() { ... }`, `~Foo() {}`, `bool operator==(...) {}`), of which only constructors were found.
- C++ calls resolve through the class: `Foo::bar()` and `ns::Foo::bar()` call sites are stored as `Foo.bar` and resolve by that qualified name (they were stored as `Foo::bar`, which never matched a symbol), so `Other::bar()` no longer competes with `Foo::bar`. `this->bar()`, `obj.bar()` and `bar()` stay plain calls (as in Java, C#, Kotlin and Swift), and now prefer the caller's own class when a scope has several `bar`s, since out-of-class methods have a container. `std::sort()` looks for `std.sort` and links nothing unless the repo defines one.
- Migration 014 blanks the content hash of C/C++ files (files with `c`/`cpp` symbols, or a `.c`, `.h`, `.cpp`, `.hpp`, `.cc`, `.cxx`, `.hxx`, `.hh` path), so the next index stores the new names and edges. A memory on a renamed method (`bar` → `Foo.bar`) has no symbol of its old qualified name to relink to and stays orphaned (kept, not deleted).

### Known limitations
- Go route prefixes are applied only within one file: a router or group passed to a function in another file (or a chi `Mount`ed sub-router) has its routes registered without the outer prefix. A router parameter in the same file also has no prefix unless it is a chi `Route`/`Group` callback. gorilla/mux is not detected.

## [1.4.0] - 2026-11-04

Upgrading: migrations 012 and 013 make the first index after upgrading a full re-index (memories are kept and relinked). Behaviour changes to check: the default database moved to the project root, symbol names resolve strictly (ambiguous or partial names are errors, never a silent guess), and some tool inputs that were silently accepted are now rejected (see Changed).

### Added
- `extract --dependency-reserve` (default `25`): percent of the budget kept for the code of the matches' direct dependencies before lower-ranked matches are packed. What the dependencies leave unused goes back to the remaining matches, then skeletons. `0` restores the 1.3.0 packing. Library: `Options.DependencyReservePercent` (0 disables, clamped to 90).
- MCP tool responses gain additive fields: `truncated` on `get_call_tree`, `get_blast_radius`, `get_tests_for_symbol` and `find_http_routes` (plus `routes_truncated` / `matches_truncated` there); `truncated`, `truncated_reason` (`limit` or `scan_cap`) and `symbols_scanned` on `search_code_patterns`; `match_type` (`exact` or `fuzzy`) on the resolved symbol of `get_code_by_symbol` (per result), `get_call_tree`, `get_blast_radius`, `get_symbol_usages` and `get_tests_for_symbol`; `candidates` on a failed `get_code_by_symbol` batch item; `symbols_total` and `files_skipped` on `reindex_project`. `IndexStats` gains `SymbolsRemoved` and `SymbolsTotal`.

### Changed
- **Symbol names resolve strictly.** Tools taking a `symbol_name` look it up by exact name, then exact qualified name. A name that matches neither is resolved by substring only when exactly one symbol (qualified name) contains it, and the response says `match_type: "fuzzy"`; several matches are an error listing up to five candidates ("ambiguous"), and no match is "not found" with suggestions. Before, any substring silently picked the first match, and `""`, `%` or `_` matched an arbitrary symbol (LIKE wildcards were not escaped). `save_symbol_memory` never uses a substring match: a partial name is rejected with suggestions instead of attaching the note to a guessed symbol. `get_code_by_symbol` reports lookup and database failures separately from "not found".
- `get_symbol_memories` with `symbol_name` returns the memories of symbols with exactly that name or qualified name (and orphaned memories last seen as that name or `Something.<name>`), not of every symbol whose name contains it.
- Input validation: `search_code_patterns` `limit` ≤ 0 and `semantic_search_symbols` `top_k` ≤ 0 are errors (before: no results / reset to 10); `top_k` above 50 is capped to 50 (was reset to 10) and `get_symbol_memories` `limit` above 100 to 100 (was reset to 20); `get_call_tree` `depth` < 1 is an error (was accepted and returned an empty tree). `file_path` arguments of `get_file_skeleton`, `find_dead_code`, `find_http_routes` and `get_symbol_memories` are normalised (backslashes, `./`, `..`, absolute paths under the project root) and must stay inside the project root; `file_path_prefix` accepts backslashes.
- **Empty lists are `[]`, not `null`:** `search_code_patterns` `results`, `semantic_search_symbols` `results`, `get_tests_for_symbol` `tests`, `get_symbol_usages` `usages`, `find_http_routes` `matches`, `get_code_by_symbol` `dependencies`, `get_modified_symbols` `symbols` / `changed_lines`, `read_architecture_rules` `sections`.
- `get_tests_for_symbol` returns tests ordered by file and line, at most 100 (`truncated` beyond); dependency and name matches are no longer mixed through a map.
- Tools config: each memory tool is enabled by its own name (`save_symbol_memory`, `get_symbol_memories`, `purge_stale_memories`); `memory` still enables all three. Before, naming any one of them also registered the other two, including the destructive `purge_stale_memories`.
- Library: `store.ResolveSymbol` takes an `allowFuzzy` flag and returns a `SymbolResolution`; `store.GetCallTree` takes the repo name and returns a truncation flag; `store.SearchCodePatterns` takes a `CodePatternFilter` and a cursor; `store.GetTestsForSymbol` / `GetTestsByNameHeuristic` return a truncation flag; `store.GetSymbolWithDependencies` resolves exact names only and returns dependency errors; `store.GetImportsForFile` (unused, returned the edge kind instead of the import) is removed.
- The default database is now `.context-link.db` in the project root (the `--project-root`, or the `[path]` given to `index`), not in the current directory, for `index`, `serve` and `extract` alike, so running them from different directories uses one index. An explicit `--db-path`, `db_path` config value or `CONTEXT_LINK_DB_PATH` is used as given (relative to the current directory). If you indexed a project from another directory without `--db-path`, move that `.context-link.db` into the project root or re-index.
- `extract --budget-bytes` and `--max-symbols-per-file` reject `0` and negative values with exit code 1 instead of silently using the defaults.

### Fixed
- `search_code_patterns` missed real matches: its SQL prefilter used only the first alternation branch (`foo|bar` searched for `foo`), took escapes and character-class contents as literals (`\x41BCD` → `41BCD`, `[xyz]+Error` → `xyz`), and cut candidates at `limit`×2 before applying the regex. The prefilter now uses only substrings every match must contain (from the parsed regex; none for alternations, classes or optional parts), and candidates are paged in file/line order with the regex applied before the limit, scanning at most 50,000 symbols.
- `get_tests_for_symbol` classified `latest.go`, `contest.go` and `testConnection()` as tests (case-insensitive `LIKE '%test_%'` with `_` a wildcard, and any name starting with `test`). Tests are now recognised by path segment and file-name convention (`_test.go`, `test_*.py`, `*.test.ts`, `*.spec.*`, `*_spec.rb`, `FooTest.java`, `tests/`, `__tests__/`, `Foo.Tests/`, ...) or a Rust `mod tests`; the name fallback is bounded and escapes wildcards.
- More than 32,766 IDs in one batch query (a first index or full re-index of a large repo) failed with "too many SQL variables", and callee keywords were silently dropped for every symbol. `GetCalleeNamesForSymbols`, `GetSymbolsByIDs`, `GetDirectDependencies`, `CountMemoriesBySymbolIDs` and the dependency/call-tree BFS now query in chunks of 500.
- `get_call_tree` and `get_blast_radius` capped at 100 edges without saying so, followed edges into other repos' symbols, and ignored row iteration errors; they now report `truncated`, stay in the served repo and return the errors. Within a depth, edges are ordered by file and line.
- `find_http_routes` `path` filter, symbol name search and the test name heuristic passed `%` and `_` to `LIKE` unescaped.
- `get_file_skeleton` and `find_dead_code` joined `../` paths onto the project root, so "does not exist" vs "no symbols" revealed which files exist outside it; backslash paths returned no dead code. Paths are cleaned and confined to the root before the filesystem is consulted.
- `reindex_project` always reported `symbols_removed: 0`; it now counts the symbols the run deleted (from deleted files, and the previous symbols of re-indexed files, as `symbols_added` counts their replacements). `files_skipped` (CLI `index` summary) subtracted deleted files, which are not among the discovered ones, and so under-counted failed files.
- Nested `.gitignore` files were not read: only the root one applied. Every directory's `.gitignore` now applies to the paths below it, with its patterns relative to that directory (`/out` in `pkg/.gitignore` ignores `pkg/out` only), and a deeper file overrides a shallower one as in git. `index`, `extract` and `serve --watch` (which watches the same directories `index` walks) all use them; the next index run drops files they exclude.
- Symlinked source files were indexed even when they pointed outside the project root, and the 1 MB limit was checked against the link instead of its target. A symlinked file is now indexed only if its target is a regular file inside the (symlink-resolved) root and at most 1 MB; links that dangle, point at directories or leave the root are skipped (with a warning for the latter). Devices, pipes and sockets with a source extension are skipped.
- Symbol keywords (FTS and embedding enrichment) were sorted alphabetically and then cut to 30, so on symbols with many callees late-alphabet names were dropped, including error types and signature types. Keywords now keep priority order (error/behaviour patterns, signature types, callees, initializer identifiers) and order of appearance, and the cap drops the least relevant ones. Takes effect when a file is re-indexed.
- Tree-sitter trees were freed only by the GC finaliser, so indexing a large repo held parsed C trees well after use. Each file's tree is now closed as soon as its symbols, dependencies and routes are extracted.
- `ONNXEmbedder` used after `Close` dereferenced the destroyed ORT session (a crash). `Close` is now idempotent and returns destroy errors, and `EmbedOne`/`EmbedBatch` after it return `vectorstore.ErrEmbedderClosed`.
- A malformed safetensors header (negative data offsets, negative dimensions, shapes whose element count overflows) panicked in `GetFloat32Tensor`, or read header bytes as tensor data. These now return errors. Only the embedded Model2Vec model is parsed today, so this was latent.
- Embedding inputs longer than 128 WordPiece tokens were truncated silently. `TokenizerOutput.Truncated` reports it and both embedders log it at debug level.
- A stored embedding whose BLOB length is not a multiple of 4 was decoded with its trailing bytes dropped and scored as valid. It is now rejected (`vectorstore.ErrCorruptEmbedding`) and skipped, with a warning, by semantic search, the vector cache and `Similarities`; `index --force` rewrites it.
- HTTP route matching (`find_http_routes` matches) compared raw string prefixes, so a `/` route matched every call site at 0.5 and `/api` matched `/apiv2`. Matching is now per path segment and the root matches only itself. Path normalisation now turns Flask `<id>` / `<int:id>` and FastAPI `{id:int}` into `:param` (Flask paths were left as written), Express `:id(\d+)` / `:id?` into `:param`, and multi-segment parameters (Flask `<path:p>`, FastAPI `{p:path}`, Express `*`, `*name`, `:p*`, `:p+`) into `*`, which matches one or more trailing segments. Stored routes are renormalised when their file is re-indexed (`index --force` for all). Matching still compares at most 200 definitions and 200 call sites, but now logs a warning when it hits that cap, and `store.MatchRoutesDetailed` returns a `Truncated` flag.
- Overlapping index runs in `serve`: a `--watch` re-index and `reindex_project` calls (which the MCP server runs concurrently) could index the same files at once, failing with `FOREIGN KEY constraint failed`, duplicating rows or attaching embeddings and memories to deleted symbol IDs. Index runs on an indexer are now serialised (a run waits for the one in progress, or gives up when its timeout ends) and `serve` uses one indexer for both, so changes seen during a run are indexed by the next one.
- `serve` shutdown closed the ONNX embedder and the database while a `--watch` re-index could still be using them. It now stops the watcher, waits for the in-flight index run, rejects new ones, and only then closes the embedder and database.
- `serve --watch` never watched directories created after startup (their Create event was dropped by the source-extension filter), so files added to a new directory were not indexed until something else triggered a re-index. New directories, and directory trees moved into the project, are now watched and indexed, skipping the same directories as `index` (`node_modules`, `vendor`, `.git`, ..., root `.gitignore`); the watcher no longer skips `bin`, `target`, `.idea` or `.vscode`, which `index` does index.
- `serve --watch` ignored renames, so a renamed file, a file moved out of the project, or every file under a renamed directory stayed indexed under its old path. Renames now trigger a re-index that removes the old paths.
- Environment variables `CONTEXT_LINK_MODEL_PATH`, `CONTEXT_LINK_VOCAB_PATH`, `CONTEXT_LINK_ORT_LIB_PATH` and `CONTEXT_LINK_TOOLS` were ignored (only keys with a default were read from the environment). Every config key is now bound to its `CONTEXT_LINK_` variable, which overrides the config file.
- `extract` loaded at most 200 routes before dropping test/vendored ones, so routes in test files could push real entry points out. All routes are filtered first; then at most 200 entry points are returned (ordered by file, line, method, path) with a warning saying how many were omitted.
- `extract` ignored a failed handler lookup for entry points (handlers came back empty); it now fails with exit code 2 like other database errors.
- `extract` ordered symbols with the same score and start line by map iteration, so which one was packed (and `files[].symbols` order) could change between runs. Ties are broken by qualified name, then symbol ID.
- `extract` treated .NET test projects (`Foo.Tests/`, `Foo.UnitTests/`, `Foo.Specs/`), Django `tests.py`, and `mock/`, `testutil/`, `testutils/` directories as production code; they are now excluded unless `--include-tests` is given.
- `extract` packed no dependency code on large repos: the matches filled the whole budget before the dependency pass ran. On paranoid (`--profile threat-model`, 50 KB) the default reserve packs 25 dependency symbols (was 0) and leaves 59 dependencies as references only (was 102); 41 matched symbols are packed instead of 46.
- Function-local variables were symbols (Go `var`/`const`, Kotlin `val`/`var`, Swift `let`/`var`, Rust `const`/`static`, JS/TS `const f = () => ...` inside a function). As the innermost span around nearby calls they took those calls' edges (`cfg -> Load` instead of `Run -> Load`); the queries now only match top-level and class/type-level declarations. On context-link: 1,442 → 1,222 symbols, 222 locals gone; `routes.go:handler`, a local `var handler` with 113 inbound edges from tests calling their own `handler := ...`, drops out of the top callees.
- Same-name symbols in one file were silently dropped: the unique key `(repo, qualified_name, file)` let `INSERT OR REPLACE` keep only the last Go `init()`, Java/C#/C++/Kotlin/Swift overload, or a Rust struct next to its `impl`. Migration `012_symbols_unique_start_line.sql` adds `start_line` to the key (index-only change, no row is deleted or cascaded). Lookups that can now see several rows are deterministic (first by file, then start line): `GetSymbolByName`, `GetSymbolByQualifiedName`, `SearchSymbolsByName`, `GetSymbolNameIndex`, memory relinking, and call resolution, where overloads count as one candidate and resolve to the first instead of becoming ambiguous. On paranoid: 210 more symbols kept (nested Python test helpers with the same name).
- Methods lost their container prefix in TypeScript abstract classes (and `abstract class` was not a symbol), Java interfaces/enums/records, C# structs/interfaces/records, Rust trait default methods and Kotlin classes/objects; Go generic receivers gave `Cache[K, V].Get` and Rust generic impls `Foo<T>.m`. They are now `Class.method` / `Cache.Get` / `Foo.m`; `impl<T> Foo<T>` is a symbol. An exported TS/JS arrow function could be extracted as `variable`; it is now always `function`.
- Deleting a file left its FTS rows, so ghost hits used up `semantic_search_symbols`/`extract` slots. The deleted-file path now goes through `store.DeleteFileIndex`, one transaction that removes the same rows as a re-index (FTS, embeddings, edges, routes, call sites, symbols) plus the file record.
- Migration 012 blanks every file hash, so the first index after upgrading is a full re-index with the new queries. Memories are relinked by qualified name and file; a memory on a method whose qualified name gained a container prefix (e.g. Kotlin `find` → `Repo.find`) stays orphaned and stale.
- Keyword (FTS5) search matched the whole query as one exact phrase, so `"token validate"` missed `validate token` and almost no natural-language query got keyword hits. Queries are now split into words, each quoted (no FTS5 syntax gets through; a NUL byte used to cause an `unterminated string` error), stopwords dropped, and the words OR-ed and ranked by BM25. camelCase/PascalCase names are also indexed as words (`validateToken` → `validate token`), so they match after the next re-index of their file (migration 013 forces it). On context-link, 0 of the top-5 hits for `validate token`, `parse file symbols` and `save memory` were keyword matches before and 13 of 15 are now; `UserAuth.validateToken` enters the top 5 for `validate token` and `SaveMemory` moves from #2 to #1 for `save memory`. On paranoid (`--profile threat-model`), 4 of 25 packed files change and the auth and config route files now rank on their queries (`authentication ...`, `configuration secret key ...`) rather than only as entry points.
- `semantic_search_symbols` applied `kind` and `file_path_prefix` after cutting the results to `top_k`×2, so a filtered query whose matches ranked lower returned nothing. The filters now run inside the vector and keyword searches, before their cuts.
- `min_similarity` was not applied to keyword-only hits, which came back with `similarity_score: 0`. Every hit now reports its cosine similarity to the query (looked up from its stored vector; 0 when it has none) and must reach `min_similarity`, so keyword matches re-rank and extend the semantic results but cannot bring in symbols below the threshold. `extract` uses the same search.
- Embeddings ignored BERT normalisation and averaged `[UNK]` into the result, so `café` and `用户登录` had cosine 1.0 and any unknown-word input cleared the 0.3 threshold against any other. The tokenizer now drops control characters, splits CJK ideographs, lowercases and strips accents (`café` = `cafe`); Model2Vec pools only real vocabulary tokens; an input with no known token embeds as the zero vector and matches nothing (also with the ONNX model). Before: `café` and `用户登录` each returned 5 unrelated hits at 0.34–0.35 on context-link; now none. Stored vectors change slightly for text with accents or unknown words; migration 013 refreshes them.
- Migration `013_reindex_for_search_changes.sql` blanks every file hash, so the first index after upgrading is a full re-index: existing databases get the camelCase name words in their FTS rows and the normalised embeddings without `index --force`. No row is deleted; memories are relinked by name and file as on any re-index.
- A switch of embedder left the "embedding dimension mismatch" warning forever, even after `index --force` re-embedded everything; vectors of the other dimension scored 0 and were returned with `min_similarity=0`; and any error reading the recorded dimension (e.g. `SQLITE_BUSY`) overwrote it. The recorded dimension is now updated once every stored vector has the current embedder's dimension (checked at startup and after every index run); vectors of another dimension and zero vectors are skipped by search; a read error is reported and changes nothing.
- A misconfigured ONNX model (missing model/vocab file or OnnxRuntime library, incompatible model) only failed on the first embedding, so `index` "succeeded" with 0 embeddings and every search errored. The ONNX embedder now loads the vocabulary, library and session and runs a test embedding at startup; on failure `index`, `serve` and `extract` log a warning and fall back to the built-in Model2Vec embedder. The three commands share one embedder setup.

## [1.3.0] - 2026-11-03

### Changed
- **Breaking:** `extract` output is now `schema_version: 2`. `files[].symbols` is a list of objects instead of names: `name`, `qualified_name`, `kind`, `start_line`, `end_line`, `offset` (byte offset in `content`), `role` (`match`, `dependency` or `outline`) and `dependencies` (resolved direct callees with file and lines).

### Added
- `serve --repo-name`, with the same meaning as on `index`.
- `.gitignore` support for `!` negation (last match wins), anchored `/pattern` and `**`.
- Migration `008_memories_repo_name.sql`: memories record their repo.
- `extract` packs the code of each match's direct dependencies after the matches and before skeletons, within the budget; dependencies that did not fit stay listed as references and are counted in a warning. `--dependency-depth 0` lists dependencies without packing their code.
- `store.GetDirectDependencies`: batch caller → direct callees lookup scoped by `repo_name`.

### Fixed
- `testdata/extract` fixtures are checked out with LF line endings (`.gitattributes`), so `budget.used_bytes` in the golden files no longer depends on `core.autocrlf`.
- Dependency edges were all attributed to the first symbol in the caller's file (often a module-level variable such as `logger` or `router`). Each call now belongs to the innermost symbol whose lines contain it, and calls in module-level statements produce no edge. On paranoid: 2,098 → 5,896 edges, 271 → 2,695 distinct callers. Affects `get_code_by_symbol`, `get_call_tree`, `get_symbol_usages`, `get_blast_radius`, `find_dead_code` and search enrichment. Migration `007_reresolve_dependencies.sql` drops the old edges, so the first index after upgrading is a full re-index; memories are relinked to their symbols.
- **Security:** `get_modified_symbols` passed `base_ref` straight to `git diff`, so a value such as `--output=<path>` could write any file. Refs starting with `-` are now rejected, and refs are resolved with `git rev-parse --verify --end-of-options` before use.
- `get_modified_symbols` returned nothing when the project root was a subfolder of the git repo and ran no diff for `include_staged=false` with `HEAD`. It now reports untracked files as added, and renamed and non-ASCII paths by their new path.
- Method and selector calls (`s.Load()`, `pkg.Func()`, `self.helper()`, `this.helper()`) now produce call edges in Go, Python, JavaScript and TypeScript; before, every cross-package Go call was missing. On context-link: 1,331 → 2,116 edges; on paranoid: 5,896 → 8,241. Callees are still matched by bare name, so common method names (`get`, `Len`, `Open`) can link to the wrong symbol.
- Editing or deleting a file left edges from unchanged callers pointing at deleted symbols. They are now linked again by name after an incremental index, or left unresolved if the callee is gone. Migration `009_reresolve_method_call_edges.sql` makes the first index after upgrading a full re-index.
- Callees were matched by bare name across the whole repo and every language, and the last symbol with the name won, so common names linked to arbitrary symbols: every Python `dict.get()` to `ConnectionManager.get`, Go `x.Len()` to `candidateHeap.Len`, `os.Open`/`sql.Open` to `store.Open`, Python calls to Go functions. Calls now resolve within the same language (JS/TS/TSX and C/C++ count as one) in widening scopes: the caller's file, its directory, the files it imports, and the rest of the repo only for a name defined once (never for Go). Several candidates in a scope give no edge unless exactly one is in the caller's own class. A receiver bound by an import (Go package, Python `import a.b` or `from m import x`, JS/TS default or namespace import) resolves only in the imported repo files, and not at all for an external package; `self`/`this` prefer the caller's class; any other receiver stays in the caller's file (Go: also its package and methods of imported packages). Python relative imports are now extracted. On context-link: 2,468 → 2,104 edges, 9 → 0 cross-language; on paranoid: 8,468 → 7,396 edges, 123 → 0 cross-language, `ConnectionManager.get` 688 → 148 inbound (the remaining ones are calls on its `db` instance). Some dynamic method calls on objects of unknown type (`profile.category_set()` from another module) no longer get an edge.
- An index run interrupted or failed between replacing a changed file and resolving edges lost the edges from unchanged callers into that file for good: the changed file was retried, the callers weren't. Files whose edges must be resolved again are now recorded in the database (`pending_resolution`) in the same transaction that drops their edges, and every run resolves all recorded files. Each file's raw calls and imports are kept (`call_sites`) so this needs no re-parse. A call left unresolved because its callee was missing now gets its edge when a file adding that name is indexed, and a call that becomes ambiguous loses it. Migration `010_scoped_resolution.sql` makes the first index after upgrading a full re-index.
- If the repo's symbols failed to load after the store phase, dependency resolution ran against no symbols, replaced the edges of every file it resolved with nothing and cleared their re-resolution marks, so the edges were lost for good. The run now fails instead and is retried next time.
- Go standard library imports (`log`, `net/http`, `errors`) mapped to a repo directory with the same name, so `log.Printf` could link into a repo package `log`. Imports under the root `go.mod`'s module path now map to exactly the directory they name, and an import path whose first element has no dot is treated as the standard library.
- `find_dead_code` reported symbols as dead when their only callers were calls the resolver deliberately leaves unlinked (a method called on an object of unknown type from another module). A symbol is now alive if any call site in the repo names it, apart from calls inside its own body.
- Indexing found 0 files when the project folder was named `vendor`, `build` or `dist`, or when `.gitignore` contained `.*` or `*`. Ignore rules no longer apply to the root.
- An interrupted or failed index run could leave files with a current hash but no symbols, so later runs skipped them. Each file is now replaced in one transaction and hashes are committed only after the run finishes; an interrupted run returns an error and is retried next time.
- `serve --project-root .` queried repo `"."` and every tool returned nothing. `index`, `serve` and `extract` now resolve the project root and repo name the same way.
- Semantic search kept a stale vector cache after `reindex_project` or a `--watch` re-index, so new and changed code was missing from vector results. The cache is now refreshed after every re-index.
- `purge_stale_memories` deleted stale memories from every repo in a shared database, and orphaned memories could relink to another repo's symbol at the same path. Both are now scoped by repo. In a shared database, legacy orphaned memories whose repo can't be determined are kept but left out of purges, relinks and reads. `get_symbol_memories` now also returns the current repo's orphaned memories.
- SQLite settings never took effect: `store.Open` passed mattn-style DSN parameters (`_foreign_keys=on`, `_journal_mode=WAL`, `_busy_timeout=5000`, ...) that `modernc.org/sqlite` ignores, so foreign keys were off, WAL and the busy timeout were not set, and `ON DELETE CASCADE` / `SET NULL` never ran. Every setting now uses the driver's `_pragma=` form and a test checks them on a file database. Migration `011_drop_dangling_symbol_refs.sql` deletes dependency edges and embeddings that point at missing symbols, marks the callers that lose an edge for re-resolution, clears dangling route handlers, and turns memories linked to a missing symbol into stale orphans whose file is re-indexed next, so they relink by name and file.
- `index --force` never detached memories before replacing every symbol, so they kept pointing at deleted symbol IDs and were no longer found by symbol name. Forced files now go through the same snapshot, detach and relink path as changed files (`stale_reason` `reindexed` until relinked).

## [1.2.0] - 2026-10-17

### Added
- `extract` subcommand: one call indexes incrementally, ranks symbols against repeated `--query` flags, and prints one JSON document (`schema_version: 1`) with HTTP `entry_points`, budget-packed `files` (full code first, then signature-only skeletons), `index` health including `parse_failures`, and `warnings`. Tests, fixtures, vendored code and migrations are excluded unless `--include-tests`. `--profile threat-model` adds security-oriented queries and boosts entry-point handlers. Exit codes: 0 ok, 1 usage error, 2 index unusable.
- HTTP route extraction in the indexer for FastAPI and Flask (decorators, `methods=`, `APIRouter(prefix=)` / `Blueprint(url_prefix=)` in the same file) and Express-style registrations in JavaScript, TypeScript and TSX. Handlers are linked to their symbols. `find_http_routes` returned nothing before this because routes were never written to the index.
- `index` summary prints the number of HTTP routes; `IndexStats` reports the files that failed to index.

### Fixed
- Files were silently dropped during indexing ("operation limit was hit"): a pooled Tree-sitter parser could be reused after a stale cancellation flag was set. Each parse now uses a fresh parser. On a 364-file repo this removed 67–68 failed files (about 19% of symbols).
- Dependency `github.com/buger/jsonparser` 1.1.1 → 1.1.2 (CVE-2026-32285, denial of service).
- CI workflow now declares `permissions: contents: read`.

### Changed
- `HybridSearch` (vector KNN + FTS5, fused with RRF) is exported from `internal/tools` and shared by `semantic_search_symbols` and `extract`.
